# hana-skill-lit-summary

给 [Hana Agent](https://openhanako.com) 用的文献总结技能：喂进一篇文献（PDF、DOI 或正文），产出结构固定、可直接交上去的中文文献总结，并排版成 Word 文档。

面向化学、化工、材料方向的研究生，按每周文献汇报的实际需要设计。

## 它解决什么问题

读完一篇文献再写成总结，最容易坏在两处：创新点写成摘要复述，可借鉴点写成"可借鉴其表征方法"这类废话。这个技能把骨架定死，让这两处无处可藏：

- 创新点固定两条，每条必须写成「相对于谁 / 新在哪 / 靠什么证据」。删掉"相对于"那行如果句子还成立，说明只写了作者做了什么，不算创新。
- 可借鉴点两到三条，每条必须落到「用在哪个样品 / 解决什么问题 / 具体怎么做 / 照搬还是改造」。"怎么做"要具体到投料、条件、观察指标、时间点。

写不出来就只写两条，不许拿空话占位。

## 四大模块

| # | 模块 | 要求 |
|---|------|------|
| 一 | 文献名片 | 三线表：题目、作者、期刊卷页年、DOI、文献类型、影响因子与分区（分列并注明口径年份） |
| 二 | 主要内容概括 | 150～250 字，只陈述不评价：体系与做法、两项关键结果、结论落点 |
| 三 | 创新点 | 固定两条，三段式 |
| 四 | 可借鉴到本课题 | 两到三条，四要素 |

没有证据链、局限分析、自我对照这类强塞的模块。判断力集中在创新点的"证据"那一行：是直接证据还是仅有相关性、对照全不全。

## 工作流程

严格分两阶段，不会跳过确认直接出文件：

```
文献 PDF / DOI
   ↓ 阶段 0：抽正文、抽关键图、核对元信息、联网查影响因子与分区、台账查重
   ↓ 阶段 1：对话框输出四模块 Markdown 草案
   ↓ 阶段 2：等你回复「同意」或「生成word」
   ↓ 阶段 3：导出 .docx + 写入文献台账 + 交付
```

## Word 排版

中文宋体、西文与数字 Times New Roman；大标题小二加粗居中，一级标题小三，二级四号，三级小四；正文小四、两端对齐、1.25 倍行距；表格为标准学术三线表（顶底线 1.5 pt、栏目线 0.75 pt、无竖线）；图片居中、最大宽 13.5 cm，配五号图题。

## 文献台账

每次导出后在 `文献总结/文献台账.csv` 记一条（DOI、题目、期刊、年份、一句话创新、一句话可借鉴、文档路径），按 DOI 去重。下次同一篇再丢进来会先提示"这篇写过"，避免重复劳动。台账路径可用环境变量 `LIT_SUMMARY_LEDGER` 覆盖。

## 安装

把整个目录放到本地技能目录：

```
~/.hanako/skills/lit-summary/
```

或在 Hana 的应用设置里以本地包形式安装本仓库（`SKILL.md` 需在包根目录）。

### 依赖

```bash
pip install python-docx pymupdf
```

`python-docx` 用于生成 Word，`pymupdf` 用于读取 PDF 与渲染页面为图片。只用 Word 导出、不用 PDF 抽图时可以不装 `pymupdf`。

## 使用

丢一个 PDF 给助手，或者说"写个文献总结"，或直接用斜杠命令 `/lit-summary`。

## 移植前必改的两处

本仓库是作者自用环境的原样备份，直接拿来用需要注意：

1. **`references/project_profile.md`** 里是作者自己课题的背景（体系、配比、表征条件）。这个文件决定"可借鉴到本课题"模块写得实不实，请替换成你自己的方向，否则输出永远是套话。
2. **`SKILL.md` 与 `scripts/ledger.py` 里的路径**是按作者本机写的（Windows 下的绝对路径、`Desktop/OH-WorkSpace` 工作区）。换机器时改成你自己的目录，`python` 也建议换成本机解释器完整路径：Windows 应用商店的 `python` 占位程序会让命令返回退出码 9009。

## 目录结构

```
lit-summary/
├── SKILL.md                        技能说明与工作流
├── references/
│   ├── structure_template.md       四大模块写法、正反例、学术化改写对照
│   ├── project_profile.md          课题背景（作者自用版本，请自行替换）
│   └── example_data.json           可直接套用的 Word 生成 JSON 骨架
└── scripts/
    ├── generate_docx.py            通用 Word 排版引擎
    ├── extract_figures.py          PDF 抽图 / 指定页渲染
    └── ledger.py                   文献台账查重、写入、列出
```

## 已知限制

- 不负责替你检索文献，只处理你给的文献。
- 扫描版 PDF 无法直接抽正文，需要 OCR 或直接贴文字。
- 影响因子与分区逐年变动，技能会注明采用的口径年份；查不到时写"待核实"，不会凭记忆填数字。
- 不同学校对文献总结的格式要求不同，模块与排版都可按需改 `structure_template.md` 与 `generate_docx.py`。
